# pi-action

Run the [Pi](https://github.com/earendil-works/pi) coding agent from GitHub Actions in non-interactive print mode (`pi --print`).

## Quick start

### 1. Add a provider secret

In **Settings → Secrets and variables → Actions**, add the API key for your model provider. The example below uses `ANTHROPIC_API_KEY`.

### 2. Add the workflow

Create `.github/workflows/pi.yml`:

<!-- prettier-ignore -->
```yaml
---
name: Pi
on:
  workflow_dispatch:
    inputs:
      prompt:
        required: true
        type: string
permissions:
  contents: read
jobs:
  pi:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout repository
        uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1  # v7.0.1
        with:
          persist-credentials: false
      - name: Run Pi
        uses: dceoy/pi-action@5c800f306333d382853eee3d9780830d3d4f3800  # unreleased (main snapshot, 2026-11-13)
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        with:
          model: anthropic/claude-opus-5
          prompt: ${{ inputs.prompt }}
```

Pi reads provider credentials from the environment (for example `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, or `GEMINI_API_KEY`); run `pi --help` for the full list. Pi's response is written to the step log.

## Automated PR loop with OpenRouter

The [Pi PR loop workflow](.github/workflows/pi-pr-loop.yml) runs the pinned [`pr-loop` Skill](https://github.com/dceoy/pr-loop) when a non-draft, non-bot pull request is opened or marked ready for review. It only accepts pull requests from the same repository whose authors are owners, members, or collaborators. Forks and arbitrary comment triggers are excluded.

Add `OPENROUTER_API_KEY` to **Settings → Secrets and variables → Actions**. The default Pi model is `openrouter/openrouter/free` (OpenRouter's no-credit free router). Free usage is rate-limited and model selection varies; reusable callers can override it with a specific `openrouter/<model-id>` if more reliable performance is needed. The workflow runs `pr-loop` (review, feedback triage, and reconciliation), **not** just the `pr-review` Skill. This can commit fixes and publish PR reviews; it never merges.

The workflow uses a trusted base-branch checkout, a SHA-pinned checkout action, a pinned pr-loop Skill (via `action.yml`), and a GitHub CLI credential helper instead of storing the token in the checkout. Permissions are limited to the operations required by the full loop. The job does not run on `synchronize`, so automated fix commits cannot trigger another loop through this workflow.

By default it uses the job's `GITHUB_TOKEN`. GitHub suppresses most workflow events generated by that token, so CI may **not** run on commits pushed during triage. Set an optional write-scoped `GH_TOKEN` Actions secret (PAT or GitHub App token with appropriate repository permissions) if fixes must trigger CI. Supply that secret explicitly when calling the workflow from another repository. Never expose credentials to fork PRs.

The workflow also supports `workflow_call`. Call it from a `pull_request` workflow, pass `OPENROUTER_API_KEY` through `secrets`, and grant `contents: write`, `pull-requests: write`, `issues: write`, `actions: read`, `checks: read`, and `statuses: read`. Pin the reusable workflow reference to a released commit SHA. `model`, `timeout-minutes`, and `runs-on` are optional inputs.

## Inputs

| Input             | Default       | Description                                                                |
| ----------------- | ------------- | -------------------------------------------------------------------------- |
| `prompt`          | Required      | Prompt to send to Pi.                                                      |
| `model`           | Pi default    | Model in `provider/model` format.                                          |
| `thinking`        | Model default | Thinking level: `off`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`. |
| `tools`           | Pi default    | Comma-separated tool allowlist, e.g. `read,grep,find,ls` for read-only.    |
| `pr-loop-ref`     | Pinned SHA    | Full commit SHA of the pr-loop skills to install.                          |
| `timeout-minutes` | `60`          | Stop Pi after this many minutes.                                           |

Each run installs the latest Pi using the [official installer](https://pi.dev/docs/latest/quickstart), so the Pi version is not pinned even when this action is pinned to a commit. The installer needs `curl` and Node.js 22.19.0 or newer with npm on the runner; the action does not set up Node.js.

Each run installs the four [pr-loop skills](https://github.com/dceoy/pr-loop) at the pinned commit into a temporary directory and makes them available to Pi. The runner needs GitHub CLI with `gh skill` support and access to the repository.

Pi runs its tools (including `bash`) without a permission prompt, so grant the job only the permissions the task needs and do not pass untrusted text as `prompt`.
